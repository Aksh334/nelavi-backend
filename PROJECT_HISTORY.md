## Update, 2026-10-18 (appended; the statements above are not rewritten)

An offline orchestration layer was added after 2026-10-16, in controlled milestones that the owner approved one at a time, followed by two read-only audits and a post-audit fix task. Details and decisions are in `CHANGELOG.md` and `ARCHITECTURE_DECISIONS.md` (OR-1 to OR-6). In order:

- **1B and 1D:** a small synchronous runner (`orchestration/run.py`) that executes an explicitly supplied list of steps for one validated Record and returns a JSON-compatible description of the run; a read-only review (1C) found no blocking defect and 1D hardened the status and input rules.
- **1E to 1J:** read-only safety preflights and the first regression runs of four existing test files, one at a time (the Research Pro file, which starts a Node process, only after the owner's explicit approval).
- **1K and 1M:** read-only readiness and contract audits.
- **1L:** an offline adapter (`orchestration/pipeline_steps.py`) that connects the runner to the existing report pipeline using injected fakes.
- **1N:** hardening of that adapter: report inputs are checked before any provider is called, dataclasses are rebuilt by keyword, failures keep safe provenance, and a record and a run are checked for consistency where that can be shown.
- **Overall audit and post-audit fixes (2026-10-18):** a repository-wide read-only audit, then fixes for one demo-server defect, one report-information loss and one pipeline robustness gap, plus test cleanup and these records (OR-3).

No live request was made to any provider in any of these steps, no dependency was installed, and nothing was staged or committed. The full test suite was last recorded as passing on 2026-10-16 and has not been re-run since; see `PROJECT_STATUS.md` for what was run on 2026-10-18.

## Update, 2026-10-24 (appended; the statements above are not rewritten)

Milestone M1 (Backend Security Readiness) was completed following owner approval of implementation decisions and safeguards (`ARCHITECTURE_DECISIONS.md` SE-1). The objective was establishing a secure, opt-in remote-access layer preparing the Python backend for future FlutterFlow web and mobile clients:
- Local development behavior remains default and unmodified when launched without `--remote`.
- In remote mode (`--remote`), Bearer authentication is enforced on all `/api/*` endpoints using `hmac.compare_digest`, reading the token from `NELAVI_AUTH_TOKEN` (or `--auth-token-env`) strictly in the server entry point.
- The web UI (`/` and `/static/*`) is disabled in remote mode (Option A), exact-origin CORS allowlisting and preflight `OPTIONS` are supported, and a minimal unauthenticated `/health` endpoint was added.
- Remote real-provider stages remain disabled by default, requiring `--allow-remote-real-providers`.
- Provider credential isolation was preserved, with `TestIsolation` updated narrowly for `hmac` and entrypoint token lookup.
- 34 new offline unit tests were added in `tests/test_remote_security.py`. The full regression suite ran offline with provider credentials unset and socket tripwires enabled: **1,957 tests, OK, 17 skipped**. No deployment, public exposure, cloud configuration, or live provider calls were made.

Later on 2026-10-24, a standalone live NVIDIA smoke test with the verified real leaf photo (`Screenshot 2026-10-06 175858.png`, 232,255 bytes, SHA-256 `e87e04a4cb91b053...`) completed Stage 1 with HTTP 200 (60.7 s, 119 tokens) but failed Stage 2 validation with `WRONG_TYPE at crop`. Root cause inspection revealed that `build_prompt()` lacked an explicit prohibition against returning `crop` as a bare string or list, and included an ambiguous instruction ("Everywhere else use a text or a list"). Following owner approval, IA-13 made the smallest justified prompt correction in `agri_pipeline/findings.py`, clarifying that `"crop"` is a JSON object with exactly the single key `"candidates"` (never a string, list, or null) and that `"crop"` and `"growth_stage"` are always objects. `validate_findings()` remained strictly unchanged. Offline regression tests covering string, list, null, and valid candidate structures were added across `tests/test_agri_pipeline.py`, `tests/test_nvidia_findings_smoke.py`, and `tests/test_nvidia_findings_rules.py`. The full offline suite ran with **1,957 tests, OK, 17 skipped**. Zero live calls or credit consumptions occurred during the repair.

On 2026-10-25, the CropSync Voice & Multilingual Learning Assistant (VA-1) was implemented and verified during a 4-hour integration sprint. The implementation delivered standard-library ElevenLabs speech-to-text (`scribe_v1`) and text-to-speech (`eleven_multilingual_v2`) integration with pluggable offline transport seams and socket tripwires; 5 precision agriculture learning lessons with complete human-reviewed trilingual translations in English, Hindi, and Telugu; interactive progress tracking; and agronomic question-answering integrating live rover soil telemetry (NPK, moisture, temperature) and low-moisture alerts. All routes were integrated into `demo_app` (`/api/voice/transcribe`, `/api/voice/synthesize`, `/api/assistant/ask`, `/api/learning/lessons`, `/api/learning/lesson`, `/api/learning/progress`) and rendered in Section 8 of the web application. Zero inline styles, zero `innerHTML`, and zero hard-coded theme colors outside CSS variables were enforced. 11 end-to-end user journeys were verified with `scripts/verify_voice_and_learning_e2e.py`, and the full offline test suite passed with **1,990 tests, OK (skipped=17)**. Zero live provider credits were consumed.
